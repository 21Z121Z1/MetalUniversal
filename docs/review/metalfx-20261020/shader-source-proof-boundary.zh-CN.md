# 同名核心shader的语义证明边界

当前`MetalEntityMotionPipeline.auditedShaders`只检查vertex/fragment使用相同Identifier且namespace为minecraft。它能排除不同ID的Iris合成程序，不能证明资源包没有在同一ID下修改顶点变形、clip或discard，也不能证明include内容仍与被审计的26.3源一致。程序描述hash区分ID、defines、layout和状态，尚不是实际源码内容hash。

后续需要把实际编译读取的shader与include内容证明绑定到它自己的异步pending compile和资源reload generation，未知或不一致的内容继续拒绝精确运动；不能用namespace或单一源码ID替代。核实还必须覆盖同名替换、include替换、异步逆序完成和reload后的旧证明失效。不能直接猜测缓存include对象的getter、所有权或可关闭时机。

本轮先从准确pinned依赖记录`ShaderSource.CachedIncludeSource`的class SHA、字段和方法签名，确认可实施的类型化接口。它只是接口证据，`sourceAdmissionGranted=false`，尚未实现或验收完整source/include语义准入。现有Temporal/FG、UI、颜色及完整producer门禁不由这份诊断解除。

3ca的实际依赖class SHA为`d1c2e467627524dddd41db3e7fa05829c2b6a9cda8d783e6303ee22e038be5ab`，include对象公开`includeResultPtr()J`。后续编译捕获在每个pending自己的ShaderSource包装器中记录实际getShader字符串与getInclude返回缓冲的SHA256。包括显式raster-storage入口；不从当前全局library补写旧pending的内容。include缓冲只在调用内借用，不保存地址、不关闭或释放原对象。完成时生成不可变快照，同一输入中途变化、缺失、超预算均保留拒绝原因。纯CPU负例覆盖同名源码/include替换、逆序完成、借用buffer的position/limit与后续改写、完成后写入及大小/条目预算。

真实客户端census按实际执行过的program记录编译输入指纹变体，最多四份，超额明确overflow；这些是累计编译诊断，不能单凭汇总数证明某一源帧的完整生产者准入。当前所有快照仍`sourceAdmissionGranted=false`。官方指纹审计只读取已有Loom缓存：先核对26.3 metadata声明的client大小和SHA1，再输出原始core/include的SHA256、字节数及import依赖；没有新下载，不把classloader第一份同名资源当作官方依据。仍需在准确SHA的CI中比对实际编译读取的内容与该原始参考，并把结果接入回放准入，不能以哈希采集完成替代该工作。
